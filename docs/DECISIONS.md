## D-001 — Missing-texture placeholder is a flat magenta square, not stamped with the item id
2026-08-27
PROJECT_PLAN §2 specifies a placeholder "stamped with the id." Rendering text into an Image
requires font setup and adds complexity disproportionate to its value at M0. Decision: return a
flat magenta ImageTexture and call push_warning() with the full resolved path. The console
warning carries the diagnostic detail; the magenta square carries the visual signal. Revisit only
if missing textures become hard to trace in a busy scene.

## D-002 — Godot config/cache dirs are pre-created in the Dockerfile
2026-08-27, corrected 2026-08-29
Docker seeds a named volume from the image contents at the mount path, including ownership —
but only on first creation. Because /home/vscode/.config/godot did not exist in the image, the
volume was created root-owned and the vscode user could not write editor settings.
Original diagnosis was correct but the remedy was only applied at runtime (chown inside the
container), so it was discarded on rebuild. Actual fix: mkdir + chown of .config, .cache, and
.local for the vscode user in the Dockerfile, placed immediately after user creation — plus
`docker rm -f <container>` and `docker volume rm samsara-roguelike-godot-config`, since an
existing volume keeps its original ownership through any number of rebuilds.
Verified: ls -ld ~/.config/godot → vscode vscode; make editor launches clean.

## D-003 — project.godot is generated by the engine, never hand-written
2026-08-27
config_version must match the pinned binary (4.7.1); a mismatch produces confusing downstream
failures. An empty project.godot is a valid project marker, but `--editor --quit` does not rewrite
it because no setting is marked dirty. Generated instead via tools/init_project.gd, which sets
application/config/name and calls ProjectSettings.save(), forcing the engine to write its own
config_version. tools/ sits outside src/ so make check does not lint it as game code.
